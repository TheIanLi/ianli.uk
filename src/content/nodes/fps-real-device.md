做 3D 网页的那两天，有两个地方看到的"卡"都不是真的。一个在我这边：我隔着远程桌面看电脑上的预览。另一个在 Claude 那边：它在 WSL 里开的浏览器没有显卡。两边看到的，都不是别人直接打开网站会看到的样子。

## 我这边：远程桌面

我当时用 UU 远程连着电脑看预览，觉得卡，问它：

> 我不知道是不是因为我在用 UU 远程的原因，确实有一点卡。但是一个网页怎么会卡呢？是因为里面沉余的代码太多了吗？就是太多没有用的东西？我记得 AI 好像都有些这种毛病，就经常写一些用处不大的代码。

它的回答是两截。没执行的代码不会让画面变卡，最多让第一次加载多下一点东西。远程桌面要把屏幕实时压成视频传过来，一直在动的 3D 画面是它最吃力的情况，既占显卡又丢帧。

光听它说我也没法信。它加了个 `?fps`：网址后面带上，角上会显示实时帧率和画质档位。这个数是电脑自己数的，隔着远程看也准。我看完回它：

> 还可以，60 以上基本上。我就说 4060 怎么可能带不起来一个网页？

卡是远程带来的，电脑本身跑得动。

帧率数字还照出来一个真问题：点节点的那一下会掉帧。那个是真卡，另记。

## Claude 那边：没有显卡的浏览器

Claude Code 跑在 WSL 里。它要看自己做出来的页面，只能在 WSL 里开一个不显示窗口的浏览器，截图给自己看。这个浏览器用不上显卡，3D 画面全靠 CPU 硬算。它量过选中节点之后每一帧花的毫秒数：

```
[798,917,783,833,783,883,883,867,1250,1117,1167,1083,1050,1083]
```

一帧要 0.8 到 1.2 秒，一秒画一帧左右。同一个页面在我电脑上是一秒 60 帧以上。

所以帧率和手感它测不了。这一点它自己说过：

> 我控制不了你的 Windows 桌面，只能在 WSL 里开一个看不见的浏览器截图，所以帧率和手感我都测不准。

它能做的是换一种量法，量那些不看显卡快慢的东西：着色器程序有没有变多，主线程忙了多少毫秒，节点在屏幕上漂了多少像素。量出来的绝对数字偏大，它只看谁排第一。

## 吃过的亏

第一版特效我说像光污染，它自己列的原因里有一条：它是在没有显卡的环境里一张张截图自查的，只看了功能有没有跑通。

上线之后手机上动画快了 1000 倍，上线前也没人发现，因为速度不对在截图上看不出来。

这个问题到现在没解决，只是知道了。它提过一个办法：我用调试模式单开一个不登录任何账号的 Chrome，它连上去，就能在我真实的显卡上操作网页、看帧率。这个办法还没试过。
