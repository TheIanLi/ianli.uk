文件里删掉的东西，提交历史里还在。仓库一公开，谁都能翻到。我的处理是不改历史，给 GitHub 一个全新的"初始提交"，旧历史留在本地一个永远不推送的分支上。

## 现象

推代码之前 Claude 做了三项检查：扫一遍当前所有文件，看有没有密钥和 IP；扫一遍整个提交历史，防止有以前提交过又删掉的东西；确认每个提交用的都是 noreply 邮箱。三项全过。

然后它又多看了一眼，发现文档里明文写着我两个子域名，一个是探针，一个是一台服务器。这是我最早提需求时自己写的，意思是"这两个别动"。它照着记进了项目的说明文件，从第一个提交起就在里面。

三项检查没拦住，是因为规则认的是 IP、密钥、邮箱的样子。域名长得和正常文字没有区别。

## 改历史被拦了

它的第一反应是改写历史：用 `git filter-branch` 把每个旧提交里的那两个名字换掉。命令发出去，被 Claude Code 自己的安全机制拒了：

```
Permission for this action was denied by the Claude Code auto mode classifier. Reason: [Git Destructive].
```

改写历史收不回来，它不让自动执行。

## 三个选项

它先把当前文件里的名字换成了泛称，提交，然后停下来让我选。A 是给 GitHub 一个全新的初始提交，内容是清理后的版本，完整历史留在本地不推。B 是我放开权限让它改写历史，每个旧提交都保留。C 是原样推上去。

我回了一个字母：A。

做法是这样：

```bash
git branch -m main history-local   # 带完整历史的分支改个名，只留在本地
git checkout --orphan main         # 新建一个没有任何历史的 main
git add -A && git commit           # 当前内容作为唯一的一个提交
```

推完它又核对了一遍：远程只有 `main` 一个分支，只有 1 个提交，新旧两个分支的文件内容完全一样，新 `main` 的全部历史里搜那两个名字是 0 次。

## 顺手加的一道保险

规则认不出域名，那就直接告诉它是哪几个词。它加了一个本地文件 `.secrets-terms`，每行一个不能出现的词，这个文件本身不进仓库。提交前的扫描脚本会读它。加完它故意放了一个带子域名的测试文件，被拦下来了（子域名我换成了星号）：

```
✗ 发现 1 处疑似敏感信息，已阻止：

  probe-test.txt:1  [私有敏感词]  ***
```

## 代价

GitHub 上只有上线之后的提交。前面 16 个小时是怎么一步步做出来的，公开的地方看不到。
