LLM-Net-Probe 是我放上 GitHub 的第一个仓库，4 月 29 日建的。一个 82 行的 Python 脚本，检查 WSL 里能不能通过代理连上大模型的接口。代码是 Gemini 写的，我粘贴进去跑；怎么放上 GitHub，也是它一步步教的。写得非常随便，到现在一个 star 都没有。

## 怎么来的

那阵子我在跟 Gemini 学 Linux。有一天突然连不上 GPT 还是 Claude 了，具体是哪个我记不清。我问 Gemini 怎么测，它给了几个办法，顺便说可以写个小脚本，当成我的第一个项目。我觉得挺有意思，就说那就做一个。

它写了一段代码，我粘贴进去，运行。然后它又教我怎么开源：先在 GitHub 网页上建仓库，再把脚本推上去。提交记录里能看到，下午 5 点 43 分建的仓库，6 点 08 分推上了 `probe.py`，前后 25 分钟。

许可证的事我一直记错了。我以为当时什么都没挂，MIT 是后来才补的。翻提交记录才发现，建仓库的那个提交里就已经带了一份 MIT 许可证，应该是照着步骤在网页上勾的，我那时候根本不知道这是什么。后来专门补许可证的是[记忆之桥](/n/memory-bridge/)，6 月 2 日补的。

## 它干了什么

脚本先看自己跑在 Windows 上还是 WSL2 里。在 WSL2 里，它用 `ip route` 找默认网关，把网关当成 Windows 主机的地址，再把代理环境变量指向主机上代理软件的端口。然后请求一次 Groq 的接口，模型是 llama-3.1-8b-instant，让它只回"网络畅通"四个字，顺便算一下耗时。

成功的话会打印：

```
[SUCCESS] API 请求成功！您的节点完美支持海外高频调用。
[INFO] 接口耗时: ... ms (不愧是地表最快 Groq!)
```

代理端口是写死在代码里的，出了错就直接退出。代码里还留着一行注释"换成了 Groq 的 API 和 Llama3 模型"，说明最早测的是别家的接口。之前是哪家、为什么换成 Groq，记录里没有。

## 6 月改了 README

最开始 README 只有一句英文介绍。6 月 1 日我让[渡鸦](/n/duya-agent/)看了一遍我 GitHub 上的几个仓库，它对这个的评价是"一个人的脚本练习，不是项目"，建议要么藏起来，要么在 README 里写清楚是练手的。第二天 README 重写了，开头就标明这是一个练手项目，代码很简陋，留着当个里程碑。

## 现在

现在它在我电脑上已经跑不通了。WSL 后来改成了镜像网络模式，代理软件在本机地址上就能直接连，默认网关变成了路由器的地址。写这篇的时候我让 Claude 试了一下：按脚本的办法找到的网关，加上那个端口，连接超时；直接连本机的代理是通的。也就是说，脚本第一步"找主机地址"就找错了。

代码一直没再改过。仓库还挂在 GitHub 上，0 个 star，0 个 fork。
