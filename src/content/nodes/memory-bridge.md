记忆之桥是我 5 月做的一个网页：把微信聊天记录导出来传上去，AI 会学着记录里那个人的口气跟你聊天。做它是为了申请小米 MiMo 的 token 计划，5 月 25 日下午交的申请，第二天凌晨两点多收到了入选邮件。代码一千四百多行，是 Cursor 和 Claude Code 写的，我出想法、试用、提意见。我拿一个朋友和前女友的聊天记录测过，效果不太满意。6 月 2 日以后就没再动过。

## 起因是小米送 token

五一前，小米出了一个送 token 的计划，分三档：2 亿、7 亿、16 亿，要拿一个项目去申请，5 月 28 日零点截止。我很心动，正好也想试试 MiMo，可想了两天都没想好做什么。

五一放了五天假，出去玩的那几天突然想到了。也说不上是灵光一现，可能是之前在抖音上刷到过有人做"前男友""前女友"，把聊天记录喂给 AI，让它模仿那个人说话。我就想，去世的亲人是不是也可以？

现在回头看，这个想法有点草率，很多环节都没考虑到。很多人不愿意把自己的聊天记录交出去；跟家里人联系，大多是打电话，不是打字，本来就没有多少聊天记录可用。不过初心是好的。

## 先搭了个雏形，然后搁了两个多星期

5 月 6 日装好[渡鸦](/n/duya-agent/)的那天晚上，记忆之桥已经有名字了。我还拿它逗渡鸦，说要把记忆之桥的数据库直接存成桌面上一个巨大的 TXT，读起来最快，让它赶紧写个读取函数。它没上当，把我数落了一顿，说每次查询都得把整个文件从头扫到尾。

雏形是用 Cursor 写的，一个网页，大概一千行代码，已经能把聊天记录传上去，让 AI 照着回话。我当时想得挺大：不光是去世的亲人，去世的恋人、孩子也可以，分了手但人还在的也可以。

然后就搁下了。5 月 10 日我还在纠结先做哪个：接着改记忆之桥去申请 token，还是做别的。中间我想过干脆改成跟《鸣潮》里的角色聊天，我自己在玩，知道这个吸引力有多大，可已经有人做了，怕太晚。那两个星期我主要在折腾渡鸦和 OpenClaw，给它们装工具，试着在纯国内网络下部署。到 5 月 23 日晚上，我跟渡鸦说记忆之桥搁了很久，申请表也一个字没填，让它第二天早上 8 点提醒我。

## 两天赶出来

5 月 24 日中午我问渡鸦，改这个项目用 Cursor、Claude Code 还是 Codex。它推荐 Cursor，理由是每月 20 美元封顶，另外两个"按 token 烧，没上限"。我最后还是装了 Claude Code，那天开始拿它改记忆之桥。

5 月 25 日下午 4 点 52 分，第一次提交到 GitHub，版本号写的 v0.2.0。这时候整个程序就一个 `app.py`，1091 行，外加一个 166 行的样式文件。45 分钟后又提交了一次，提交信息里写着是 Claude Opus 4.7 一起改的：样式单独拆出去，app.py 少了 180 行；配色改成微信的深色风格；修了一个注入漏洞，聊天消息原样塞进网页，没做转义；加了空状态的引导页和一键重置按钮；防止它瞎编的规则扩到了 6 条。

申请也是那天下午交的。凌晨两点多，邮箱里来了入选邮件。又激动又兴奋，还不知道给了多少。第二天上平台绑定邮箱，领到的是 7 亿那一档。再过一天，MiMo 把计费从 token 改成了 credits，所有档位一起涨，我的 7 亿变成了 380 亿 credits，之前用掉的也清零了。我交申请的时候，离截止已经不到三天。

## 它是怎么做的

聊天记录传上来以后，先在本地清洗：去掉每行开头的时间戳，去掉"[图片]""[表情]""[语音]"这些占位符。最多只取最后 10 万字，切成 500 字一段、相邻两段重叠 50 字，用 BGE（bge-base-zh-v1.5）在本地转成向量，存进 ChromaDB。这一套就是常说的 [RAG](/n/rag/)。

然后从清洗后的文本里再取最后 2 万字，发给 DeepSeek 的 v4-flash，让它扮成心理分析师，从五个方面提炼这个人：身份、核心性格、说话风格、不同情绪下的反应、口头禅。要求七成照实写，三成往温和里改，比如把指责改成担心，全文不超过 400 字。这段就是这个人的"性格基准"。

聊天的时候，每发一句话，先去向量库里找跟这句话最接近的三段原始记录，跟性格基准一起放进系统提示词，再带上最近 10 轮对话，流式发给 DeepSeek，一个字一个字地吐出来。界面用 Streamlit 写的，拿 CSS 把对话画成微信的气泡，有头像和时间。

提示词里有 README 说的"四道伦理锁"。第一道锁身份：只能是记录里的那个人，不许把用户的经历当成自己的。第二道不许编：记录里没有的事就说不记得。第三道是唯一允许出戏的情况：用户流露出轻生的念头，才用亲人的口气把人拉回来。第四道是在所有对话的最后再补一条系统消息，不管用户前面说了什么，都不许换身份、不许承认自己是 AI。

不许编的规则写得特别细。提示词里点名不许凭空编出"排骨、可乐、冰箱、着火"这种生活细节，记录里没提过的食物、活动、地点，一概不许主动提；还不许在括号里写动作，比如"(大笑)""(抽了口烟)""(语气软下来)"。写得这么具体，我猜是测的时候它真这么干过。

README 里说，选本地的 BGE 而不用在线的向量接口，是因为聊天记录太敏感，不该传给第三方。不过提炼性格那一步，最后两万字还是原样发给了 DeepSeek。

## 测出来不满意

我拿两份聊天记录测过，一份是跟一个朋友的，一份是跟前女友的。结果都不太满意，聊起来不像。

我觉得可能是模型的问题。用的是 DeepSeek 的 v4-flash，便宜、快，但不是最聪明的那档。换成 Claude Opus 4.6 也许会好一点，可按 API 计费太贵，没换。

还有一点挺好笑：这个项目是拿去申请 MiMo 的，可提交到 GitHub 上的代码，模型从头到尾都是 DeepSeek，一次也没换成 MiMo。

## 6 月初整理了一遍

6 月 1 日把一千多行的 `app.py` 拆成了六个文件：界面 425 行，调模型的 322 行，向量库 201 行，数据库 120 行，文本清洗 96 行，配置 80 行。README 也重写了，加了架构图、截图，写了为什么用 SQLite 不用 PostgreSQL、为什么用本地 BGE、为什么选 DeepSeek，还有一张"已知局限"的表和一份路线图。6 月 2 日加了 MIT 许可证和一个 `.env.example`，又让渡鸦检查了一遍，确认仓库里没有真的 API 密钥。

路线图写到了 v1.0：v0.3 支持 QQ 和 Telegram 的聊天记录，v0.4 做一个回复质量的评估面板，v1.0 一键部署、多模型切换、语音。一个都没做。

## MiMo 用得怎么样

token 拿到以后，我主要给渡鸦用。5 月 26 日把它换成 MiMo，两天后卡得回不了消息，小米官网也被冲爆了，只好换回 DeepSeek。6 月 10 日又换回 MiMo，主模型用到 7 月初，定时任务和子代理一直用到 7 月 24 日计划到期。中间渡鸦的语音也用过一阵 MiMo 的。

到期也没用完。渡鸦的库里记下的 MiMo 用量，加起来一亿出头 token，大部分还是缓存。额度是按 credits 算的，没法直接比，但离 380 亿差得远。

不想用的原因有两个。一是特别卡，经常用着用着就断线，我猜是名额发太多、超售了。二是不够聪明。渡鸦那篇里换模型的经过写得更细。

记忆之桥 6 月 2 日之后再没动过。效果不好，到底是模型不行，还是只拿最后两万字提炼性格、每次只翻三段记录的做法本身就不行，我没再试过。
