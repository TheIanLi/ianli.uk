no-mistakes 是 Kun Chen 写的工具，代码推上去之前自动跑一遍审查、测试和检查。我在 WSL 里用它，每一步都报 403，原因是它的后台进程没带上我的代理设置。修复我提给了他：6 月 24 日晚上提的，30 日上午合并，前后五天半。最后的改动是 14 个文件、986 行，代码是 Claude Code 写的。

## 为什么用它

我一直在关注 Kun Chen，喜欢他讲事情的逻辑，观点也比较客观。他发了这个项目，我马上就去试了。它正好是我缺的东西：我的项目全是 AI 写的，我自己没有 review 的能力，代码好不好我看不出来。

第一次用大概是 6 月 8 日前后，在 main 分支上跑，什么输出都没有。后来才弄明白，它管的是推送之前那一道，只看这次要推的改动，不负责审已经写好的老代码。

## 6 月 24 日

那天下午我在用它检查 [Agent 配置快照](/n/agent-config-snapshot/)那个项目，突然不能用了。审查、测试，每一步都是同一句：

```
Failed to authenticate. API Error: 403 Request not allowed
```

可是在终端里直接跑 `claude --print`，是正常的。

我让 Claude Code 一种一种可能去查。具体猜过哪几种、各自怎么排除的，我现在记不清了，记录也没留下。我记得的是自己冒出来的一个想法：作者人在美国，他会不会从来没碰到过国内用户的情况？会不会跟我电脑上开着代理有关？

顺着这个查下去，最后翻了它的源码。no-mistakes 干活的不是我敲命令的那个终端。它有一个后台进程，由 systemd 启动，再由后台进程去调 Claude。systemd 启动的进程不继承终端里的环境变量，它的服务定义里只写了 `HOME` 和 `PATH` 两项。我的代理地址放在终端的环境变量里，后台进程拿不到，请求直接发了出去。在我这儿，直连就是 403。

验证的办法是 Claude Code 给的，造一个和后台进程一样干净的环境再跑一次：

```bash
env -i HOME=$HOME PATH=$PATH claude --print hi
```

403 出来了。把代理变量加回去，又好了。

修法是安装后台服务的时候，把当时终端里的代理变量一起写进服务定义。晚上 8 点 52 分，[PR #322](https://github.com/kunchenguid/no-mistakes/pull/322) 提了上去。

## 被打回

第二天我还是不放心，让 Claude Code 把自己当成审这个 PR 的人，从头再查一遍，又改了一轮。

27 日凌晨 2 点 50 分 Kun Chen 回复了，我是早上 8 点半在邮箱里看到的，挺激动。他说这个修复有用，但 Windows 上的自动测试是红的，问题就出在新加的代码里。Windows 的环境变量名不分大小写，代码把 `HTTPS_PROXY` 和 `https_proxy` 当成两个变量各取了一次，取到的是同一个，结果里就多出一条重复的。

我问，之前查了那么多遍，为什么没发现。原因很简单：测试都是在 WSL 里跑的，也就是 Linux。Linux 分大小写，测试全过，就当没问题了。从头到尾没在 Windows 上跑过一次。

## 返工

重复那个问题本身不难改。麻烦的是改完再过一遍 no-mistakes，它自己的审查开始一条一条往外报。写进服务文件的代理地址可能带着账号密码，所以文件权限要收紧。收紧的写法又有漏洞，中间有一小段时间文件是别人能读的。Claude Code 看完说都是真问题，都改了。

最要命的一条是我们自己带进来的。原来的服务定义不管在哪生成都一模一样，no-mistakes 靠比对它来决定要不要重装服务。加了代理以后，在一个没设代理的终端里启动，生成出来的定义就不带代理。它一比对，觉得变了，重装，把之前写好的代理冲掉，403 又回来了。为了修这个 bug 写的代码，换一种情况会把这个 bug 原样带回来。这条到 28 日才修掉：当前环境里没有代理时，沿用磁盘上那份里已经写好的。

27 日下午是最乱的时候。改好的版本已经推到了我的 fork 上，PR 里原来的 5 个提交换成了 8 个，可我以为 no-mistakes 那一遍还没跑完。我搞不清现在算什么状态，Kun Chen 看不看得到，一度想先撤回来。偏偏这时候 Claude Code 的额度用完了。

晚上换成 Codex 接着跑。我提了几条要求：把这个仓库的贡献规则通读一遍，严格照着来；必须过完 no-mistakes 再推；Windows 必须测。改到这个量我也有点怕，万一人家对这一块有自己的想法呢。

28 日上午在 Windows 上把整套测试跑了一遍。有三个测试检查的是 Linux 那套文件权限，在 Windows 上本来就不成立，加了跳过。中午前后我在手机上看到 PR 的检查里有红叉，以为 Windows 又挂了。查下来是 4 项检查被取消了：前面连着推了好几次，每推一次，上一次还在跑的检查就被取消。真正的测试在 Linux、macOS、Windows 上都是绿的。

## 等

29 日主分支又往前走了十几个提交，Claude Code 把我的分支接到最新的上面，内容一个字没变。但这一推，检查又清空了。fork 过来的 PR，自动测试要作者本人点一下才会跑，我这边触发不了。

那两天我老去刷那个页面，算美国那边现在几点。30 日早上心情不太好，怀疑是不是哪里还不合规矩。9 点 36 分，合并了。到合并时一共 14 个提交。

## 没搞定的

合并之后我才知道，进了主分支不等于进了正式发布的版本。简历上那句话我改过一次。

当时还留了一个问题没处理。代理一旦写进服务定义，光把终端里的变量清掉是去不掉的，得重装服务。这是有意这么做的，不然又会被冲掉。但加进去容易，拿掉麻烦。当时说合并以后再看，后面怎么样了我记不清。

最烦的从头到尾是同一件事：我没有 review 的能力。986 行里实现是 351 行，测试 627 行，哪一行我都没法自己判断对不对，也看不出是不是写得太啰嗦、太乱。我能做的是让几个 AI 互相查，把测试在 Windows 上也跑一遍，剩下的就是等懂的人点头。靠外面的东西，心里还是不踏实。

no-mistakes 我现在偶尔还用。
